fix: Windows CI 的 PowerShell 解析错误 + 3.9 上的两个测试自身缺陷

run #159：ubuntu-3.12 全绿，但另外两个矩阵仍红，各自原因不同。

1) windows-3.12 —— 根本不是测试失败，是 shell 选错了

   ParserError: Missing '(' after 'if' in if statement.
     |  8 |  if ! python -c "import mcp" 2>/dev/null; then

   Windows runner 的默认 shell 是 pwsh，不是 bash。if ! 与 2>/dev/null 都是
   bash 语法，整个 step 在执行前就解析失败了。注意 Lint 那一步是 success
   —— 它是另一个 step，这种「同一步里第一行就炸」的形态很容易被误判成
   测试问题。

   → 改用 shell: python，把条件判断与子进程调用全放进 Python。
     三个平台行为一致，也不受将来引号转义的影响。

2) ubuntu-3.9 —— 是我自己写的两个测试有缺陷

   a) test_mcp_selfcheck_survives_missing_ai
      ModuleNotFoundError: No module named 'mcp'
      3.9 上 mcp 本来就装不上，测试却直接 import 了 mcp.server。

      → 加 pytest.importorskip("mcp")，与 tests/test_mcp.py 保持一致。

   b) test_web_health_survives_missing_ai
      ImportError: No module named 'httpx'
      屏蔽 httpx 之后走 TestClient，但 starlette 的 TestClient 本身就
      import httpx —— 等于砸自己的脚，测的根本不是被测代码。

      → 改为直接调用 _ai_status()。web.server 只在懒导入时才碰 ai.client，
        这样才真正验证「AI 层缺依赖时健康检查优雅降级」这一件事。

本地按两种矩阵口径分别验证：
  含 mcp（3.12 口径）：532 passed，覆盖率 91.08%
  不含 mcp（3.9 口径）：511 passed / 3 skipped，覆盖率 91.37%，exit 0
